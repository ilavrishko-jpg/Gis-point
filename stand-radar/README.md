# Стенд-радар

Пошук лідів на виставці з телефона — замість паперових роздруківок з Excel.

Одна HTML-сторінка без збірки та без бекенду: `index.html`. Відкривається у браузері
з файлу, з внутрішнього хостингу або як опублікований артефакт.

## Що вміє

- **Пошук** по всіх колонках бази одразу: назва компанії, номер стенда, людина,
  сегмент, будь-який текст. Кнопка `123` перемикає клавіатуру на цифрову — для
  швидкого набору номера стенда.
- **Фільтри**: країна, пріоритет (Tier), джерело, статус розмови, «не відвідані».
- **Розклад зустрічей** (іконка календаря): підтверджені зустрічі за часом, з
  лічильником у шапці; ті, що без часу, йдуть під своїм днем окремо.
- **Статуси з бази** — «Зустріч підтверджено», «Зацікавлені», «Виявити
  потребу», «Відмова» — окремий вимір фільтра, не плутається з тим, що ти
  сам відмічаєш на стенді.
- **Картка ліда**: спершу блок «Що з ним робити» (пропозиція та нотатки з бази),
  далі статус розмови, власна нотатка, контакти кнопками (подзвонити / написати /
  сайт) і повний список усіх полів файлу — нічого не губиться.
- **Робота на стенді**: статус (Поговорили / Гарячий / Пізніше / Не цікаво),
  рядок «головне по ліду» (видно просто в списку) і **журнал контактів** —
  окремий запис на кожен дотик, з часом і автором, який можна змінити чи
  видалити. Зверху видно прогрес «опрацьовано з усіх».
- **Експорт** після виставки: CSV у буфер обміну або збереження файлом.

## Дані

У сторінку вшита база MSPO 2026 — 146 записів з двох вивантажень
(`ІТ-аутсорсинг`, 119, і `FlyBy`, 27). Апка відкривається вже заповненою, без
імпорту й без мережі. Збірка бази — `data/build_base.py`, вихідний файл
`data/base.json`; скрипт додатково:

- розбирає колонку «Коментар» на **Гачок / Сегмент / Пріоритет / Група** —
  саме звідти беруться смуга пріоритету та блок «Що з ним робити»;
- відновлює назву компанії з домену пошти там, де клітинка порожня, і лише
  якщо цей домен уже зустрічається в базі з назвою (34 з 41 рядка); решті
  показує сам домен. У картці такий лід підписаний окремо;
- зводить «Дата зустрічі» та «Час зустрічі» в одне поле з ключем сортування —
  на цьому працює розклад.

Свою базу теж можна довантажити поверх: `.xlsx`, `.xls`, `.csv`, `.tsv`. Файл
читається на самому пристрої. Можна додати кілька файлів — кожен стає окремим «джерелом»,
кожен аркуш книги теж. Заголовок таблиці шукається в перших восьми рядках, тож
титульні рядки над шапкою не заважають.

Колонки зіставляються з полями апки автоматично (українські та англійські назви,
разом з відмінками). Якщо щось потрапило не туди — меню → «Які колонки за що
відповідають» правиться вручну, список оновлюється одразу.

## Де що зберігається

| Дані | Місце |
|---|---|
| База лідів | `localStorage` пристрою + спільне сховище артефакта |
| Статуси, підсумки та журнали | те саме, з синхронізацією між учасниками команди |
| Ім'я автора нотаток | лише `localStorage` |

Коли сторінка відкрита як артефакт із увімкненим `db`, база та нотатки
розходяться між усіма, хто має доступ: достатньо завантажити Excel один раз із
будь-якого телефона. Як звичайний файл (без `db`) апка теж повністю робоча —
просто дані лишаються на одному пристрої.

Кнопка «Підготувати 3 питання цьому ліду» з'являється тільки там, де доступна
можливість `sample`, і працює лише за явним натисканням.
