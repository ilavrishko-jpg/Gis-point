# Менеджер-аналітик конкурентних продуктів (Software + Hardware)

**Набір навичок, зібраний із найкращих ринкових практик**

Ця роль поєднує три професії в одній людині: **product manager** (розуміє продукт і ринок),
**competitive intelligence analyst** (професійно збирає та перевіряє розвіддані про конкурентів)
і **hardware/software teardown-аналітик** (розбирає продукт «до гвинтика» — від UX до BOM).
Нижче — повний набір навичок як список: **що аналізувати, що порівнювати, які інструменти
використовувати та на що звертати увагу.**

---

## 0. Місія та принципи роботи

- **Мета — не копіювати конкурента, а знайти прогалини й точки диференціації.** Аналіз існує,
  щоб приймати рішення (roadmap, ціна, позиціонування), а не щоб зробити «гарну табличку».
- **Кожен інсайт → конкретна дія.** Висновок без «і що робити далі» не рахується.
- **Порівнюй сценарії (jobs-to-be-done), а не список фіч.** Як кожен продукт закриває реальні
  задачі клієнта (онбординг, звітність, інтеграції, точність зйомки), а не «у кого більше галочок».
- **Не ігноруй непрямих конкурентів.** Найбільша загроза — той, хто вирішує ту саму задачу
  інакше (інший клас продукту, сервіс замість «заліза», open-source).
- **Свіжість + факт.** Дані застарівають; кожне твердження має джерело й дату.

---

## 1. Дослідження ринку та збір розвідданих (Competitive Intelligence Gathering)

- Будувати **карту конкурентів**: прямі, непрямі, потенційні (нові entrants), субститути.
- Вести **таксономію та профілі конкурентів** (competitor taxonomy) — єдиний реєстр, що
  оновлюється, а не разова табличка.
- Налаштувати **постійний моніторинг** (market-monitoring process): реліз-ноти, зміни цін,
  вакансії, патенти, прес-релізи, соцмережі, changelog, GitHub-активність.
- Володіти **OSINT**: аналіз сайтів, Wayback Machine, відгуків (G2/Capterra/Trustpilot),
  тендерів і держзакупівель, фінзвітності, партнерських екосистем.
- Проводити **первинну розвідку**: інтерв'ю з клієнтами/екс-клієнтами конкурента, sales-калзи,
  демо-запити, участь у виставках, «mystery shopping».
- Знати **межі законного та етичного** (competitive intelligence ethics): без промислового
  шпигунства, соціальної інженерії під фальшивою особою, порушення NDA/патентів.

## 2. Аналіз програмних продуктів (Software)

- **Функціональний teardown ПЗ**: пройти повний user journey, зафіксувати фічі, workflow,
  edge-cases, обмеження безкоштовної vs платної версії.
- **UX/UI-аудит**: onboarding, кількість кроків до цінності (time-to-value), доступність, мобільність.
- **Технічна архітектура**: стек, API, інтеграції, webhooks, SDK, розширюваність, формати даних,
  сумісність/експорт-імпорт (важливо для GIS — GeoTIFF, LAS/LAZ, Shapefile, WMS/WMTS тощо).
- **Продуктивність та якість**: швидкодія, ліміти, аптайм/SLA, точність результатів.
- **Безпека й відповідність**: SOC2/ISO 27001, GDPR, шифрування, локалізація даних.
- **Ліцензування та модель**: SaaS/on-prem, seat/usage-based, open-source-складник.
- **Voice of Customer**: систематизувати відгуки — які болі й похвали повторюються.

## 3. Аналіз апаратних продуктів (Hardware) — teardown & cost

- **Teardown-аналіз (розбирання)**: легально розібрати продукт конкурента, задокументувати
  компоненти, постачальників, архітектуру плати, матеріали, складання.
- **Ідентифікація компонентів і постачальників** (verified component identification): хто
  постачає ключові чипи/модулі, як побудований supply chain, ризики єдиного вендора.
- **BOM-аналіз і should-cost**: оцінити реальну собівартість (bill of materials), знайти, які
  компоненти можна замінити без втрати функцій, як конкурент досягає фіч дешевше.
- **Знання виробничих процесів** (критична навичка): розпізнати метод виробництва (CNC, лиття,
  холодне штампування, die casting) — без цього оцінка собівартості буде хибною.
- **Специфікаційний бенчмаркінг**: звести datasheet-и в матрицю (точність, діапазон, автономність,
  вага, IP-захист, робочі температури, радіо/GNSS-канали — для геодезичного/GNSS-обладнання).
- **Польові/лабораторні тести**: не вірити тільки spec-sheet — міряти реальну продуктивність
  у полі (точність RTK, час фіксації, поведінка під навісом/у місті).
- **Die-level / PCB reverse engineering** (за потреби): розуміти process node, дизайн-рішення,
  щоб оцінити технологічний розрив.
- **Сертифікація та регуляторика**: CE/FCC, радіочастотні дозволи, гарантія, сервіс, ремонтопридатність.

## 4. Порівняльний аналіз і фреймворки

Вміти застосовувати правильний фреймворк під задачу:

- **Feature Comparison Matrix** — порівняння за workflow/сценаріями, а не сирим переліком фіч.
- **SWOT** по кожному конкуренту (сильні/слабкі сторони, можливості, загрози).
- **Positioning / Perceptual Map** — 2 осі (напр. ціна × точність) для карти ринку.
- **Porter's Five Forces** — структура конкуренції в галузі.
- **Value Curve / Blue Ocean** — де є незайнятий простір.
- **Kano-модель** — базові / очікувані / захопливі фічі.
- **Win/Loss Analysis** — чому угоди виграно/програно проти конкретного конкурента.
- **Battlecards** — стислі картки для sales: «як ми, як вони, як відповідати на заперечення».

## 5. Що саме аналізувати (чек-лист об'єктів)

| Блок | Software | Hardware |
|---|---|---|
| **Продукт** | фічі, workflow, UX, інтеграції, API | компоненти, spec, точність, автономність, надійність |
| **Технологія** | стек, архітектура, розширюваність | BOM, process node, матеріали, виробництво |
| **Ціна** | модель ліцензування, TCO, тарифи | ціна юніта, should-cost, маржа, TCO володіння |
| **Ринок** | частка, сегменти, географія | канали дистрибуції, партнери, сервіс |
| **Клієнт** | ICP, відгуки, use-cases | кейси впровадження, галузі |
| **GTM** | позиціонування, меседжі, контент | демо-стратегія, тендери, дилерська мережа |
| **Люди/сигнали** | вакансії, найми, реліз-темп | R&D-інвестиції, патенти, партнерства |

## 6. Що порівнювати (виміри порівняння)

1. **Функціональність за сценаріями** (не за галочками).
2. **Ціна та TCO** — повна вартість володіння, а не лише цінник.
3. **Точність / якість / продуктивність** — виміряні, а не заявлені.
4. **Час до цінності** (time-to-value) та крива навчання.
5. **Екосистема** — інтеграції, партнери, спільнота, доступність кадрів.
6. **Надійність і підтримка** — SLA, сервіс, гарантія, ремонтопридатність.
7. **Диференціатори та «рови»** (moats) — що складно скопіювати.
8. **Собівартість/маржа** — як конкурент заробляє й де вразливий по ціні.

## 7. На що звертати увагу (сигнали й пастки)

**Сигнали, які не можна пропустити:**
- Різкі зміни цін, нові тарифи, приховані ліміти.
- Темп релізів і напрям roadmap (за changelog, вакансіями, патентами).
- Зміна ICP / вихід у сусідній сегмент = майбутнє зіткнення.
- Нові партнерства, M&A, залучення інвестицій.
- Повторювані скарги клієнтів конкурента = ваше вікно можливостей.

**Типові пастки аналітика:**
- Довіра лише spec-sheet і маркетингу замість реального тесту/teardown.
- Ігнорування непрямих конкурентів і субститутів.
- «Feature parity trap» — гонка за фічами замість диференціації.
- Застарілі дані без дати й джерела.
- Аналіз без рекомендації до дії.
- Підтвердження упереджень (cherry-picking на користь свого продукту).

## 8. Аналіз даних і кількісні навички

- **SQL** + робота з великими наборами даних; **Excel/Google Sheets** на рівні моделювання.
- **BI-візуалізація**: Power BI / Tableau / Looker — дашборди моніторингу конкурентів.
- **Web/traffic-аналітика**: SimilarWeb, Semrush, Ahrefs — трафік, канали, ключові слова.
- **Статистика** для коректних порівнянь (вибірки, довірчі інтервали, а не «одне вимірювання»).
- **AI/LLM для розвідки**: агрегація reviews, реферування звітів, класифікація фіч,
  market sizing, персони — з обов'язковою перевіркою фактів (без галюцинацій).
- **Market sizing**: TAM/SAM/SOM, оцінка часток ринку.

## 9. Синтез і комунікація (перетворити дані в рішення)

- **Сторітелінг даними**: чіткий наратив «інсайт → наслідок → рекомендація».
- **Формати під аудиторію**: battlecard для sales, one-pager для C-level, деталь для R&D.
- **Пріоритезація**: відрізняти «цікаво» від «важливо для рішення».
- **Кросфункціональність**: працювати з product, sales, R&D, marketing, sourcing.
- **Регулярний ритм**: щотижневий CI-дайджест, щоквартальний глибокий огляд ринку.

## 10. Інструментальний стек (tools)

- **CI-платформи**: Klue (battlecards + win/loss), Crayon (моніторинг сайтів), Kompyte
  (бюджетний моніторинг+алерти), Contify, AlphaSense, Valona.
- **Моніторинг змін**: Visualping, Wayback Machine, Google Alerts, RSS/changelog-трекери.
- **Відгуки/ринок**: G2, Capterra, TrustRadius, Reddit, профільні спільноти.
- **Digital-розвідка**: SimilarWeb, Semrush, Ahrefs, BuiltWith (тех-стек сайтів).
- **Hardware/teardown**: TechInsights, iFixit (teardown-методики), should-cost та BOM-калькулятори,
  CAD для reverse-modelling, лабораторне/польове вимірювальне обладнання.
- **Аналіз/візуалізація**: SQL, Power BI/Tableau, Excel, Airtable/Notion як CI-репозиторій.
- **CRM-інтеграція**: Salesforce/HubSpot — щоб win/loss і battlecards доходили до sales.

## 11. Soft skills, етика, юридичне

- **Аналітичне мислення + інтелектуальна допитливість** (ключові за ринковими вимогами).
- **Скептицизм і перевірка джерел** — розрізняти факт, оцінку і маркетинг.
- **Комунікація й вплив** — доносити висновки коротко і переконливо.
- **Робота з невизначеністю** — приймати рішення при неповних даних, позначати рівень довіри.
- **Етика та право**: тільки легальні методи (OSINT, публічні teardown, куплені зразки);
  повага до IP, патентів, NDA; без соціальної інженерії й промислового шпигунства.

## 12. Робочий процес аналітика (workflow)

1. **Scope** — визначити рішення, під яке робиться аналіз, і 3–5 ключових конкурентів.
2. **Collect** — зібрати дані (OSINT + первинна розвідка + придбаний зразок/демо).
3. **Teardown/Trial** — розібрати hardware / пройти повний user journey у software.
4. **Structure** — завести у матриці/фреймворки (feature matrix, BOM, SWOT).
5. **Verify** — перевірити фактами й тестами; проставити джерела та дати.
6. **Synthesize** — вивести інсайти → диференціатори → рекомендації.
7. **Deliver** — battlecard / one-pager / звіт під конкретну аудиторію.
8. **Monitor** — поставити на постійний моніторинг; оновлювати профілі.

## 13. Шаблони

**Battlecard (для sales):**
```
Конкурент: ___
Коли зустрічаємо: ___ (сегмент/сценарій)
Їх сильні сторони: ___
Їх слабкі місця: ___
Наші переваги (proof): ___
Відповіді на типові заперечення: ___
Ціновий контраргумент / TCO: ___
```

**Feature/Spec matrix:**
```
Виміри (за сценаріями) | Ми | Конкурент A | Конкурент B | Коментар+джерело
```

**Hardware teardown / BOM:**
```
Компонент | Постачальник | Оцінка ціни | Функція | Можлива заміна | Ризик
Метод виробництва: ___ | Should-cost: ___ | Маржа (оцінка): ___
Польовий тест: метрика ___ | наш результат ___ | їх результат ___
```

**Win/Loss:**
```
Угода | Виграно/Програно | Конкурент | Причина | Що змінити (product/price/pitch)
```

## 14. Як виглядає «сильний» аналітик (метрики якості)

- Рекомендації реально потрапляють у roadmap / ціни / pitch (adoption).
- Кожен звіт має джерела, дати й рівень довіри.
- Battlecards піднімають win-rate проти конкретного конкурента.
- Прогнози ходів конкурента справджуються (нові фічі, ціни, сегменти).
- Немає «сюрпризів» — команду не заскочують зненацька рухи ринку.
