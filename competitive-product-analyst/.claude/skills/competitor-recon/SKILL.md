# Competitor Recon — збір розвідданих по конкуренту

## Коли застосовувати
Крок Collect (SKILLSET §1, §5). Перед teardown і порівнянням — зібрати сирі факти з дати й джерелом.

## Джерела (пройти по чек-листу)
- **Сайт + продукт**: сторінки продукту, pricing, docs/API, changelog/release-notes, статус SLA.
- **Ринок/відгуки**: G2, Capterra, TrustRadius, Reddit, профільні спільноти — повторювані болі/похвали.
- **Digital-сліди**: трафік і канали (SimilarWeb/Semrush — за наявності), тех-стек сайту (BuiltWith),
  Wayback Machine (як змінювались меседжі/ціни).
- **Сигнали компанії**: вакансії (куди інвестують R&D/GTM), новини, прес-релізи, раунди, M&A,
  патенти, партнери й дистриб'ютори, участь у тендерах/держзакупівлях.
- **Первинна розвідка** (позначай як план, не вигадуй результати): офіційне демо/тріал, дзвінок sales,
  розмови з екс-клієнтами, виставки.

## Алгоритм
1. Постав 5–8 цільових пошукових запитів (продукт, ціна, «X vs», «X reviews», «X alternatives»).
2. Витягни факти у картку (нижче). Кожен факт → `джерело + дата`.
3. Познач **рівень довіри**: `факт` (2+ джерела) / `1 джерело` / `[оцінка]`.
4. Зафіксуй **прогалини**: чого не знайшов → у список «потребує первинної розвідки».

## Картка recon (шаблон)
```
Компанія / продукт: ___
Категорія (прямий / непрямий / субститут): ___
ICP та сегменти: ___
Гео / ринки: ___
Ціна та модель: ___ [джерело, дата]
Ключові фічі / spec: ___ [джерело]
Канали та партнери: ___
Сигнали (наймання, релізи, раунди, патенти): ___
Повторювані відгуки (болі/похвали): ___ [G2/Capterra, дата]
Прогалини (невідомо): ___
Рівень довіри загалом: ___
```

## Межі
Тільки публічні/легальні джерела. Немає даних — пиши «невідомо», не додумуй.
