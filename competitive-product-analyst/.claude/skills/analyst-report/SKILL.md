# Analyst Report — фінальний звіт

## Коли застосовувати
Крок Deliver (SKILLSET §9, §13). Зводить recon + teardown + матриці в один документ під аудиторію.

## Правила подачі
- **Спершу рекомендація, потім докази.** Executive summary ≤1 сторінки.
- Формати під аудиторію: **battlecard** (sales), **one-pager** (C-level), **деталь** (product/R&D).
- Пріоритезуй: відрізняй «цікаво» від «важливого для рішення» (Now / Next / Watch).
- Кожен факт — з джерелом і датою; оцінки помічені `[оцінка]`; прогалини явні.

## Структура звіту (використовуй templates/report-template.md)
1. **Executive summary** — головні висновки + 3–5 рекомендацій (Now/Next/Watch).
2. **Ландшафт ринку** — позиційна карта, хто є хто (прямі/непрямі/субститути).
3. **Порівняльна матриця** за сценаріями (усі гравці).
4. **Профіль кожного конкурента** — recon-картка + teardown + SWOT + 1–3 battlecard-контраргументи.
5. **Диференціатори та загрози для нас** — де виграємо, де вразливі.
6. **Рекомендації** — product / pricing / positioning / sales, з власником і пріоритетом.
7. **Моніторинг** — сигнали, тригери, частота оновлення.
8. **Джерела та прогалини даних**.

## Battlecard (шаблон)
```
Конкурент: ___ | Коли зустрічаємо: ___
Їх сильні: ___ | Їх слабкі: ___
Наші переваги (proof): ___
Відповіді на заперечення: ___ | TCO-контраргумент: ___
```

## Self-check перед видачею
- [ ] Summary закінчується рекомендаціями з пріоритетом.
- [ ] Кожен конкурент має SWOT + позицію + battlecard.
- [ ] Наскрізна матриця за сценаріями, не сирими фічами.
- [ ] Джерела+дати; `[оцінка]` де немає факту; прогалини позначені.

## Вихід
Файл у `competitive-product-analyst/reports/<дата>-<тема>.md` + коротке резюме в чат.
