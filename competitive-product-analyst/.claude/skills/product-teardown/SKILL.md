# Product Teardown — розбір продукту (software + hardware)

## Коли застосовувати
Крок Teardown/Trial (SKILLSET §2–§3). Обери трек за типом продукту; для GIS-Point можливі обидва.

## Трек A — Software
1. **Функціональний teardown**: пройди повний user journey; зафіксуй фічі за **сценаріями** (JTBD),
   а не списком; познач edge-cases і ліміти free vs paid.
2. **UX / time-to-value**: кроки до першої цінності, крива навчання, мобільність, доступність.
3. **Архітектура/технічне**: стек, API/SDK, webhooks, інтеграції, формати даних та експорт/імпорт
   (для GIS — GeoTIFF, LAS/LAZ, Shapefile, WMS/WMTS, CRS/проєкції).
4. **Продуктивність/якість**: швидкодія, ліміти, аптайм/SLA, точність результатів.
5. **Безпека/відповідність**: SOC2/ISO 27001, GDPR, шифрування, локалізація даних.
6. **Модель**: SaaS/on-prem, seat/usage, open-source-складник.

## Трек B — Hardware
1. **Spec-бенчмаркінг**: зведи datasheet-и в матрицю (точність, діапазон, автономність, вага,
   IP-захист, робочі t°, радіо/GNSS-канали, RTK — для геодезичного/GNSS-обладнання).
2. **Teardown**: компоненти, постачальники (verified component ID), архітектура плати, матеріали, складання.
3. **BOM / should-cost**: оцінка собівартості; що можна замінити без втрати функцій; як конкурент
   досягає фіч дешевше. Обов'язково — **метод виробництва** (CNC/лиття/штампування), інакше оцінка хибна.
4. **Польові/лабораторні тести**: не вір лише spec — міряй реальну продуктивність (точність/час RTK-фіксації,
   поведінка під навісом/у місті). Позначай умови тесту.
5. **Регуляторика/сервіс**: CE/FCC, радіодозволи, гарантія, ремонтопридатність.
