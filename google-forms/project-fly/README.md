# Project Fly (Flyby) — Google Форма зворотного звʼязку

Генератор Google Форми для збору зворотного звʼязку від **потенційних клієнтів**
(виробники / інтегратори дронів) про систему **оптичної навігації Project Fly / Flyby**
в умовах GPS-denied (глушіння/спуфінг).

Питання взяті з таблиці-опитувальника:
<https://docs.google.com/spreadsheets/d/1h_J6pSCXu1VTy9kbKTDpUJDeE8JWZQMimXKG1E6q7NQ/edit>

## Що всередині

| Файл | Призначення |
| --- | --- |
| [`create-form.gs`](./create-form.gs) | Google Apps Script — загальний discovery: повна Google Форма (44 питання, блоки A–L). |
| [`meeting-guide-manufacturer.md`](./meeting-guide-manufacturer.md) | **Гід для живої зустрічі з виробником** (з місцем для нотаток): точність по місіях, SWaP, протоколи інтеграції, день/ніч, ціна-тригер переходу від конкурентів. |
| [`create-form-manufacturer.gs`](./create-form-manufacturer.gs) | Apps Script — та сама виробнича анкета у вигляді Google Форми (якщо треба надіслати цифрово). |
| `README.md` | Інструкція запуску та мапінг питань. |

### Який файл коли брати

- **Зустріч 1:1 з виробником** → відкрий [`meeting-guide-manufacturer.md`](./meeting-guide-manufacturer.md) і веди нотатки прямо в ньому.
- **Надіслати виробнику анкету онлайн** → згенеруй форму з [`create-form-manufacturer.gs`](./create-form-manufacturer.gs) (функція `createFlybyManufacturerForm`).
- **Широкий discovery по ринку** → [`create-form.gs`](./create-form.gs) (функція `createProjectFlyForm`).

> У цьому середовищі немає прямого доступу до Google Forms API, тож форма
> генерується через **Google Apps Script** — це офіційний, повторюваний спосіб
> програмно створити Google Форму. Скрипт можна запускати скільки завгодно разів.

## Як згенерувати форму (2 хвилини)

1. Відкрий <https://script.google.com> → **New project**.
2. Скопіюй увесь вміст [`create-form.gs`](./create-form.gs) і встав у редактор
   (замінивши стандартний `Code.gs`).
3. Зверху обери функцію **`createProjectFlyForm`** → натисни **Run**.
4. При першому запуску дозволь доступ (**Authorize** — потрібні права на створення
   Форм на твоєму Drive).
5. Відкрий **View → Logs** (або **Executions**) — там будуть посилання:
   - **Edit URL** — редагувати форму;
   - **Published URL** — надсилати респондентам.

Готову форму можна далі допрацьовувати вручну (лого, тема, логіка переходів тощо).

## Структура форми

- **Вступ** — опис проєкту + збір email респондента.
- **Стартові поля** — Компанія / підрозділ, Імʼя та роль (обовʼязкові).
- **Блоки A–L** — кожен блок = окрема сторінка (section) з питаннями.
- **Фінал** — подяка.

Типи питань підібрані під зміст: відкриті — абзац, структуровані — вибір/чекбокси,
шкала (стійкість до спуфінгу), сітка-ранжування (ціна / швидкість / надійність).

> **Примітка.** Внутрішня колонка таблиці «Що валідуємо / навіщо» у форму навмисно
> **не винесена** — це внутрішня мета інтервʼю, її не варто показувати клієнту.

## Мапінг: блок → кількість питань

| Блок | Тема | Питань |
| --- | --- | --- |
| A | Контекст і роль | 3 |
| B | Реальний біль (GPS-denied) | 4 |
| C | Поточні рішення | 4 |
| D | Технічні вимоги (SWaP-C) | 6 |
| E | Сценарії та платформи | 3 |
| F | Дані карт і місії | 3 |
| G | Економіка та закупівля | 5 |
| H | Кінцевий користувач | 3 |
| I | Масштабування / експорт | 4 |
| J | Модель партнерства | 4 |
| K | Конкуренти | 2 |
| L | Наступні кроки | 4 |
| **Разом** | | **45** питань (44 з таблиці + додаткове поле контактів) |

## Гіпотези для валідації (внутрішнє)

Форма непрямо перевіряє 4 ключові гіпотези з таблиці — вони **не** є окремими
питаннями для клієнта, а закриваються відповідями у відповідних блоках:

1. **ЦІНА** — який % від вартості дрона ринок проковтне (бенчмарк TFL ~10–20%) → блок G.
2. **ТОЧНІСТЬ** — 5–30 м достатньо чи для strike треба <5 м → блок D.
3. **ФОРМАТ** — OEM-модуль vs ліцензія → блок J.
4. **ЕКСПОРТ** — що робить рішення продаваним поза Україною → блок I.
