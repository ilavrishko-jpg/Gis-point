# Plane: проєкт «GIS-Point Operations»

Тут лежить декларативний опис операційного проєкту GIS-Point у Plane і скрипт,
який доводить робочий простір до цього стану через Plane REST API.

## Що створюється

**Проєкт:** `GIS-Point Operations`, ідентифікатор `OPS`.

**Стадії канбану** (у цьому порядку, зліва направо на дошці):

| Стадія | Група Plane | Що означає |
| --- | --- | --- |
| `Backlog` | backlog | Зафіксовано, але ще не взято в роботу |
| `Todo` | unstarted | Закомічено на поточний горизонт, готове до підхоплення |
| `In Progress` | started | Хтось активно робить. Діє ліміт WIP |
| `In Review` | started | Зроблено, чекає на рев'ю / погодження / передачу |
| `Done` | completed | Прийнято й завершено |
| `Cancelled` | cancelled | Свідомо відкинуто. Не видаляємо — це історія рішень |

**Теги (labels)** — горизонт планування: `Weekly`, `Monthly`, `Quarterly`,
`Semiannual`, `Annual`. Правила роботи з ними — у [`kanban-playbook.md`](./kanban-playbook.md).

**Команда** — учасники з `config.json` додаються до проєкту з ролями
`admin` / `member` / `guest`.

**Стартові задачі** — по одній на кожен горизонт, як приклад розмітки тегами.

## Як запустити

1. У Plane: **Profile settings → API tokens** → створити токен.
2. Взяти slug робочого простору — це частина URL після домену
   (`https://app.plane.so/<slug>/projects/...`).
3. Вписати slug і команду в `config.json`:

   ```json
   "workspace_slug": "gis-point",
   "members": [
     { "email": "ім'я@gis-point.com", "role": "admin" },
     { "email": "ім'я@gis-point.com", "role": "member" }
   ]
   ```

4. Запустити:

   ```bash
   export PLANE_API_KEY=plane_api_...
   export PLANE_BASE_URL=https://api.plane.so     # self-hosted: https://plane.gis-point.com
   python3 ops/plane/plane_setup.py --dry-run     # показати план, нічого не змінювати
   python3 ops/plane/plane_setup.py               # застосувати
   ```

Залежностей немає — лише Python 3.9+.

### Прапорці

| Прапорець | Дія |
| --- | --- |
| `--dry-run` | Читає стан і друкує, що зробив би. Нічого не пише |
| `--prune-states` | Видаляє стадії, яких немає в `config.json` (напр. дефолтні зайві). Якщо в стадії вже є задачі, Plane відмовить — скрипт це переживе й скаже |
| `--skip-seed` | Не створювати стартові задачі |
| `--config ШЛЯХ` | Інший файл конфігурації |

Скрипт **ідемпотентний**: створює те, чого немає, підрівнює те, що розійшлося,
і не чіпає решту. Можна ганяти скільки завгодно разів — зокрема після правок у
`config.json`.

## Якщо API недоступний — руками в UI

Порядок той самий, 10 хвилин:

1. **Create project** → назва `GIS-Point Operations`, ідентифікатор `OPS`,
   доступ **Public** (щоб уся команда бачила дошку).
2. **Project settings → States**: перейменувати/додати стадії з таблиці вище.
   `In Review` треба додати вручну — у групу **Started**, одразу після `In Progress`.
3. **Project settings → Labels**: додати п'ять тегів горизонтів.
4. **Workspace settings → Members**: запросити людей у робочий простір.
   Потім **Project settings → Members** — додати їх у проєкт із ролями.
5. На дошці перемкнути вигляд на **Board (Kanban)** і згрупувати за **State**.
   Зберегти як вигляд за замовчуванням для проєкту.

## Обмеження

`members` через публічний API у деяких версіях Plane закритий. Якщо скрипт
отримає відмову на цьому кроці, він надрукує список людей і те, куди їх додати
руками — решта налаштувань при цьому вже застосована.
