# Стандарт навички (SKILL.md)

Кожна навичка бота FlyBy має відповідати цьому стандарту. Перевіряє `skill-author` перед пропозицією.

## Frontmatter (обов'язково)
```yaml
---
name: kebab-case-назва        # унікальна, коротка
description: >-               # ЧІТКІ тригери «коли застосовувати» — щоб бот сам знав, коли викликати
  Що робить + етап + у яких ситуаціях застосовувати (конкретні слова-тригери).
---
```

## Тіло (єдина структура)
1. **Коли застосовувати** — конкретні ситуації/фрази-тригери; на якому етапі.
2. **Кроки** — мінімальні, по дієслову.
3. **Шаблон** — готовий до заповнення (де доречно).
4. **Gate етапу (вхід/вихід)** — що має бути правдою, щоб зайти й щоб вийти далі.
5. **Вихід** — який артефакт-доказ дає навичка.

## Критерії якості (чек-лист)
- [ ] Одна навичка = одна зона відповідальності й один етап (0–5).
- [ ] Description дає однозначний тригер виклику.
- [ ] Є блок **Gate етапу (вхід/вихід)** з критеріями.
- [ ] Веде до артефакту-доказу, а не до думки; не вигадує даних.
- [ ] Не дублює наявну навичку (звірено з `registry.md`).
- [ ] Прив'язана до системи 6 етапів (`product-lifecycle-map`).

## Іменування
- Навичка: `kebab-case`, по суті дії (`market-manufacturer-research`, не `research-stuff`).
- Папка = name; файл завжди `SKILL.md`.
