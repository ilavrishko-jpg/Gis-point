# MVP Delivery & Validation (MVP і польова валідація)

## Коли застосовувати
Коли визначена найближча віха-MVP (Етап 4.1). Мета — побудувати мінімум, який дає реальний доказ
у полі, і зробити висновок «підтвердилось / міняємо».

## Кроки
1. **Мінімальний обсяг:** тільки те, що доводить головну гіпотезу продукту. Ріж усе інше.
2. **Критерії валідації:** заздалегідь визнач, що вважаємо успіхом пілоту (вимірювано, до тесту).
3. **Пілот/польовий тест:** реальні умови застосування; фіксуй дані, а не враження.
4. **Зворотний зв'язок:** від операторів/замовників; розділяй «сподобалось» і «використали б / купили б».
5. **Ітерація:** рішення keep / fix / pivot за критеріями; онови роадмеп.

## Шаблон
```
MVP-обсяг (must, ріж решту): ___
Критерії успіху пілоту (до тесту): ___
Умови польового тесту: ___
Результати (дані, не враження): ___
Зворотний зв'язок (використали б/купили б?): ___
Рішення: keep / fix / pivot — бо ___. Наступна ітерація: ___
```

## Правила якості
- Критерії успіху фіксуй ДО тесту — інакше підженемо висновок під результат.
- «Сподобалось» ≠ валідація. Валідація — це поведінка (застосували, замовили, готові платити).

## Gate етапу (вхід/вихід)
- **Вхід:** є найближча віха-MVP з роадмепу.
- **Вихід:** MVP пройшов критерії пілоту АБО зафіксовано, що і чому міняємо (fix/pivot).

## Вихід
План MVP + результати пілоту + рішення → відкриває Етап 5 (запуск) або нову ітерацію.
