# Agent Architect (бот вирощує агентів)

## Коли застосовувати
- Напрямок стабільно тягне окремий контекст, кілька навичок і власні інструменти.
- Основний діалог перевантажується цією темою — її треба винести в агента.
- Користувач прямо просить нового агента.

## Рубрика рішення (потрібно ≥2 з умов)
Див. `governance/agent-decision-rubric.md`:
1. Тема повторюється й вимагає власного контексту/памʼяті.
2. Потрібен свій набір навичок (≥2–3) або окремі інструменти (напр. WebSearch для дослідження).
3. Тема заважає основному діалогу або потребує паралельної роботи.
4. Є чіткий власник/зона відповідальності.

## Алгоритм
1. Прогони напрямок через рубрику. <2 умов — лишити навичкою, не плодити агента.
2. Звірся з `governance/registry.md` — чи немає вже такого агента.
3. Опиши агента: зона, які навички використовує, які інструменти, коли викликати.
4. Напиши `.claude/agents/<name>.md` (frontmatter: name, description-тригер, tools + тіло-інструкція).
5. Онови `registry.md` і `CHANGELOG.md`.
6. Оформи як пропозицію (PR) з `governance/agent-proposal-template.md`. Не зливай самостійно.

## Правила якості
- Агент = зона з кількох навичок + власний контекст. Одна навичка агента не робить.
- Не дублюй наявних агентів. Прибирай тих, хто не використовується (звірка з реєстром).

## Вихід
Готовий файл агента + оновлені `registry.md` і `CHANGELOG.md` + PR-пропозиція з обґрунтуванням за рубрикою.
