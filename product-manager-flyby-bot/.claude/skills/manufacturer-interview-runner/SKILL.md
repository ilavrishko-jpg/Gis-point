# Manufacturer Interview Runner (проведення й синтез опитувань)

## Коли застосовувати
Коли опитувальник готовий і починається збір відповідей (крок 1.3). Мета — не просто зібрати, а
звести у структуру, з якої видно інсайти під припущення Етапу 0.

## Кроки
1. **Запис.** Кожну відповідь заноси в єдиний шаблон (нижче), по одному запису на виробника.
   Розділяй факт (що сказали) і інтерпретацію (що це означає).
2. **Крос-матриця.** Зведи всіх у таблицю «виробник × ключове питання» — так видно патерни й розкид.
3. **Синтез.** Виділи: що спільне (сигнал), де розходяться (сегменти?), що здивувало (нове припущення).
4. **Перевірка припущень.** Для кожного припущення Етапу 0 признач статус: підтверджено / спростовано / невизначено.
5. **Оновлення.** Нові питання — назад у `discovery-questionnaire-builder`; нові виробники — у лонгліст.

## Шаблон запису інтерв'ю
```
Виробник: ___  · Дата: ___ · Формат: лист/дзвінок/форма
Технічні (ключове): ___
Регуляторні (ключове): ___
Фінансові (ключове): ___
Несподіване: ___
Факт vs інтерпретація: ___
Цитата (за наявності): "___"
```

## Шаблон звідної матриці інсайтів
```
| Питання/тема | Виробник A | B | C | … | Патерн / висновок |
Підтверджені припущення: ___
Спростовані: ___
Нові гіпотези: ___
```

## Правила якості
- Не підганяй відповіді під бажаний висновок. Суперечність — це інсайт, а не шум.
- n=1 не патерн: сигнал фіксуй, коли повторюється у кількох виробників.

## Gate етапу (вхід/вихід)
- **Вхід:** готовий опитувальник і лонгліст.
- **Вихід:** опитано ≥ цільової к-сті (напр. 8–10); є ≥5 інсайтів; кожне припущення Етапу 0 має статус.

## Вихід
База відповідей + звідна матриця інсайтів зі статусами припущень → живить Етап 2 (вимоги).
