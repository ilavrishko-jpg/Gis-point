# Idea Intake & Hypothesis (оформлення ідеї)

## Коли застосовувати
Найперший крок будь-якого продукту. Є сира ідея/запит власника, треба зафіксувати її так, щоб
дослідження було цілеспрямованим, а не «походимо-подивимось». Виходом живиться весь `PLAN.md`.

## Кроки
1. **Проблема одним реченням** — чию й яку болю розв'язуємо (без згадки рішення).
2. **Гіпотеза цінності** — «Ми віримо, що <сегмент> отримає <цінність>, бо <причина>».
3. **Ризиковані припущення (3–5)** — те, що якщо хибне, вбиває ідею. Пріоритезуй за «ризик × невідомість».
4. **Критерій успіху** — вимірюваний сигнал, що ідея жива (напр. «≥8 з 10 виробників підтверджують потребу X»).
5. **Для кого / контекст** — сегмент, сценарій використання, чому саме БПЛА.
6. Передай найризикованіші припущення в Етап 1 (дослідження) як питання для перевірки.

## Шаблон (one-pager ідеї)
```
Продукт (робоча назва):
Проблема (1 речення):
Гіпотеза цінності: Ми віримо, що ___ отримає ___, бо ___.
Ризиковані припущення (з пріоритетом):
  1) ___  (ризик: вис/сер/низ · невідомість: вис/сер/низ)
  2) ___
  3) ___
Критерій успіху (вимірюваний):
Для кого / сценарій:
Чому зараз:
Що НЕ робимо на цьому етапі (межі):
```

## Gate етапу (вхід/вихід)
- **Вхід:** є ідея/запит власника.
- **Вихід:** є вимірюваний критерій успіху і ≥1 ризиковане припущення, оформлене як питання для дослідження.

## Вихід
Заповнений one-pager ідеї + список припущень, що йдуть у `discovery-questionnaire-builder`.
