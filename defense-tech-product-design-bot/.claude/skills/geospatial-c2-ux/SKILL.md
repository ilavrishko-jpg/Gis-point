# Geospatial & C2 UX (Фаза 3 · спеціалізація)

## Коли застосовувати
Продукт містить карту, координати, шари, real-time позиції/треки, ISR/розвідку, situational awareness
чи командно-штабний (C2) інтерфейс. Це прямий міст GIS-експертизи GIS-Point у дефенс-тек.

## Принципи геопросторового UX
1. **Карта — це інтерфейс, а не картинка.** Проєктуй взаємодію: шари, фільтри, вибір, вимір, малювання,
   контекстні дії по об'єкту. Оператор мусить читати обстановку, а не «гортати мапу».
2. **Керування шарами під навантаженням.** Багато шарів = ризик хаосу. Пресети під задачу/роль,
   швидке вмикання/приховування, розумні дефолти, «панічне» очищення до критичного мінімуму.
3. **Координати без помилок.** Явно познач систему (WGS84 / MGRS / UTM / geographic), дай перемикання
   і копіювання у форматі, який очікує суміжник (артилерія, авіація). Неоднозначність координат = ціна помилки.
4. **Situational awareness перш за все.** Свої / чужі / невідомі — миттєво розрізняються (форма+колір, не лише колір).
   Актуальність даних видно завжди: свіже vs застаріле, джерело (супутник/БПЛА/сенсор), час.
5. **Sensor fusion без перевантаження.** Зводь кілька джерел в одну картину, але дай оператору довіряти
   й розрізняти їх: звідки трек, наскільки свіжий, наскільки певний.
6. **Degraded-геопростір.** Офлайн-тайли/кеш карти, робота при втраті GPS/зв'язку, деградація до останніх
   відомих позицій із явним маркуванням «дані застарілі на X хв».

## Алгоритм
1. Визнач геопросторові задачі оператора з mission flow (Фаза 1): що шукає, вимірює, наносить, передає.
2. Спроєктуй базову карту + систему шарів (пресети під роль/задачу).
3. Визнач символіку: свої/чужі/невідомі, типи об'єктів; розрізнення без опори лише на колір (для дальтонізму/ночі).
4. Продумай координатний контракт із суміжниками (формати, копіювання, точність).
5. Заклади стани: офлайн-карта, втрата GPS, застарілі треки, конфлікт джерел.
6. Прожени через `defense-ux-design` (щільність, degraded, human factors).

## Чек-ліст (доповнює ворота 3→4)
- [ ] Явно вказана й перемикана координатна система; формат узгоджено із суміжниками.
- [ ] Свої/чужі/невідомі розрізняються формою+кольором (не лише кольором).
- [ ] Актуальність і джерело кожного шару/треку видно оператору.
- [ ] Керування шарами не перевантажує (пресети, швидке приховування).
- [ ] Офлайн-карта і поведінка при втраті GPS спроєктовані.
- [ ] Sensor fusion не приховує невизначеність джерел.

## Вихід
**Карто-центричний прототип + специфікація шарів/символіки/координат.** Живиться у загальний design spec Фази 3.
