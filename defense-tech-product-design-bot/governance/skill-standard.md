# Стандарт навички (SKILL.md)

Кожна навичка помічника має відповідати цьому стандарту. Перевіряє `skill-author` перед пропозицією.

## Frontmatter (обов'язково)
```yaml
---
name: kebab-case-назва        # унікальна, коротка
description: >-               # ЧІТКІ тригери «коли застосовувати» — щоб помічник сам знав, коли викликати
  Що робить + у яких ситуаціях застосовувати (конкретні слова-тригери) + до якої фази належить.
---
```

## Тіло (єдина структура)
1. **Коли застосовувати** — конкретні ситуації/фрази-тригери + номер фази.
2. **Алгоритм / Кроки** — мінімальні, по дієслову.
3. **Чек-ліст фази** — пункти, які треба закрити (узгоджені з `stage-gates.md`).
4. **Шаблон / артефакт** — готовий до заповнення вихідний документ фази.
5. **Degraded-first перевірка** — як рішення поводиться в офлайн/ніч/стрес (де доречно).
6. **Вихід** — який артефакт фази народжується і що він змінює.

## Критерії якості (чек-лист)
- [ ] Одна навичка = одна фаза/зона відповідальності (не змішує теми).
- [ ] Description дає однозначний тригер виклику і називає фазу.
- [ ] Вміщається стисло (≈1 сторінка); чек-ліст — критичні пункти першими.
- [ ] Прив'язана до методології (Double Diamond / JTBD / OODA / human factors), де доречно.
- [ ] Має явний артефакт фази на виході.
- [ ] Не дублює наявну навичку (звірено з `registry.md`).

## Іменування
- Навичка: `kebab-case`, по суті дії (`field-validation`, не `testing-stuff`).
- Папка = name; файл завжди `SKILL.md`.
