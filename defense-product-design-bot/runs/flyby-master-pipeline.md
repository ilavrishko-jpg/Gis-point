# Fly by — Майстер-пайплайн (Продукт × Актив/Токенізація)

> Єдина логічна цепочка проєкту Fly by у два паралельні треки, зшиті залежностями.
> Готовий до імпорту в Notion-трекер «Fly by — Трекер задач» (поля: Трек · Етап · Тип · Пріоритет · Виконує · Експерт · Статус).
> Легенда «Виконує»: 🟢 Я+Claude · 🟡 Спільно · 🔴 Експерт. Дата: 2026-08-13.

## Логіка цепочки (як треки зшиті)
```
ТРЕК A — ПРОДУКТ (від ідеї до реалізації)
П1 Discovery ─► П2 Definition ─► П3 Design ─► П4 Validate ─► П5 Deliver ─► П6 Learn
      │                │ (економіка, актив)        │ (пілот де-ризикує інвестицію)
      ▼                ▼                            ▼
ТРЕК B — АКТИВ І ТОКЕНІЗАЦІЯ
            E1 Аналіз активу+модель ─► E2 Юридика/Legal Opinion ─► E3 Токенізація ─► E4 Меморандум+roadmap
```
**Ключові зшивки (dependency-мости):**
- **A2 (Definition + юніт-економіка) → E1** — актив і його вартість неможливо оцінити без визначеного продукту й економіки.
- **A2/A5 (dual-use, експортний контроль IP навігації) → E2.3/E2.5** — класифікація токена й регуляторика спираються на характер IP.
- **E1 + E2 (апрув) → E3** — концепція токенізації лише після узгодженого активу і юр-структури.
- **A4 (пілотна валідація на борту) → E4** — доказ, що продукт працює, підсилює меморандум і залучення.
- **A2.5 фінмодель ↔ E4.3 фінмодель інвестора** — одна модель, два погляди (продуктовий і інвесторський).

## Порядок запуску (що робимо зараз)
1. **A1.4** — опитати 2–3 виробники (закриває N1/N7/ціну/документи) → паралельно **A2.4** рішення про SKU.
2. **B1.1–B1.3** — визначити актив + оцінка + інвестмодель (спираються на A2 економіку).
3. **B2.1/B2.3** — підключити юриста: юр-структура + класифікація токена (Legal Opinion).
4. Далі **A3 Design** ∥ **E3 Токенізація** — паралельно, коли закриті ворота A2→3 і E1/E2.
5. Фінал: **A4 пілот** де-ризикує → **E4 меморандум** → залучення.
