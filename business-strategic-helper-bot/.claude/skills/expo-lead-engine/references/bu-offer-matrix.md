# Крок 5: сегмент × розмір → бізнес-юніт → оффер → тригер

Правило: **одна компанія = один основний BU.** Запасний BU допускається, але позначається явно
(`target_bu = BU-3 / alt BU-2`) і НЕ згадується в першій розмові — розпорошений захід вбиває конверсію.

## Матриця вибору BU

| Сегмент | Fast (10–50) | Core (50–250) | Divisional / Enterprise (250+) |
|---|---|---|---|
| `UAV-OEM` | **BU-3** (нав. стек як компонент) | **BU-3** + alt BU-2 | **BU-3** у конкретний продуктовий юніт |
| `SENSOR` | **BU-2** (софт навколо заліза) | **BU-2** + alt BU-1 | **BU-2** у R&D-юніт |
| `EO-DATA` | **BU-1** | **BU-1** + alt BU-2 | **BU-2** (платформа) + BU-1 на пікові обсяги |
| `SURVEY` | **BU-1** | **BU-1** (production capacity) | **BU-1** у виробничий дивізіон |
| `GIS-SW` | **BU-2** (dedicated team) | **BU-2** | **BU-2** у продуктову лінійку |
| `DEF-INT` | **BU-3** | **BU-3** + alt BU-2 | **BU-3** у програму/проєкт, через технічного чемпіона |
| `INFRA` | — (мало) | **BU-1** (інспекція активів) | **BU-1/BU-2** у департамент експлуатації або ІТ |
| `GOV` | — | **BU-1** | **BU-1/BU-2** через тендер/рамкову угоду |

## Оффери по BU

### BU-1 — Обробка геоданих
| Оффер | Кому найкраще | Спостережуваний тригер (що маємо побачити ДО розмови) |
|---|---|---|
| Пікова production-потужність (overflow) | SURVEY, EO-DATA | виграний великий контракт, анонс нового регіону, вакансії операторів обробки |
| Класифікація й контроль якості хмар точок | SURVEY, INFRA | новий LiDAR у флоті, скарги на якість, вимоги замовника до точності |
| 3D-моделі, DTM/DSM, цифрові двійники | INFRA, GOV | програма цифровізації активів, тендер на 3D |
| Виділена виробнича команда (extension) | SURVEY 50–250 | дефіцит інженерів, ріст обсягів, сезонність |

### BU-2 — Розробка ПЗ
| Оффер | Кому найкраще | Тригер |
|---|---|---|
| Web-GIS / геопортал / платформа даних | EO-DATA, GOV, INFRA | застарілий вебсайт-в'ювер, анонс «нової платформи», legacy-стек |
| Софт навколо заліза (десктоп/бортовий/хмарний пайплайн) | SENSOR, UAV-OEM | новий сенсор/платформа без софту, скарги на ПЗ у відгуках |
| Виділена команда розробки з гео-експертизою | GIS-SW, EO-DATA | багато відкритих вакансій GIS/backend, довгий roadmap |
| Інтеграції та міграції (формати, SDK, API, on-prem) | GIS-SW, GOV | зміна стандарту, вимога on-prem, партнерські інтеграції |

### BU-3 — Навігаційні рішення для БПЛА
| Оффер | Кому найкраще | Тригер |
|---|---|---|
| Навігація без GNSS (visual / terrain-referenced) | UAV-OEM, DEF-INT | заяви про роботу в умовах РЕБ, вимоги замовника до GPS-denied, тендер МО |
| Геоприв'язка та позиціонування за зображенням і картою | UAV-OEM, SENSOR | новий payload, вимога до точності координат цілі/знімка |
| Підготовка бортових картографічних даних | UAV-OEM, DEF-INT | вихід на новий регіон експлуатації, експорт у нову країну |
| Інтеграція нав-стеку в існуючу платформу | DEF-INT, UAV-OEM 250+ | нова платформа в лінійці, партнерство з автопілотом |

## Правило заходу за розміром
- `Fast` — оффер = готовий пакет із ціною-орієнтиром і швидким пілотом.
- `Core` — оффер = вирішення конкретного вузького місця у їхньому процесі, з метрикою.
- `Divisional/Enterprise` — оффер = технічний пілот у ОДНОМУ юніті + вхід у vendor-процес.
  Ніколи не заходимо «пропозицією для компанії» — тільки для юніта з іменем.

## Що фіксувати в базі після Кроку 5
`target_bu`, `offer` (одним рядком, конкретно), `trigger` (факт + джерело), `pain_hypothesis` (чернетка).
Немає спостережуваного тригера — оффер обирається за сегментом, але `hypothesis_confidence` не вище `M`.
