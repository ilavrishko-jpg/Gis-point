# KPI / Smart Numbers Scorecard

## Коли застосовувати
«Які KPI ставити», «що міряти команді/людині», побудова дашборда, «не розуміємо,
чи рухаємось», оцінка здоров'я бізнесу.

## Принципи метрик за Харнішем
- **Smart Number (розумне число)** — одне число, що найкраще показує стан зони зараз.
- **Одне число на людину/команду** — кожен має 1 щоденну або тижневу метрику, на яку впливає.
- **Leading > Lagging.** Випереджаючі метрики (дзвінки, демо, час циклу) керованіші за
  результатні (дохід) — став хоча б одну leading на кожну ключову мету.
- **Видимість.** Метрика, якої не видно щодня/щотижня, не працює.

## Як підібрати (алгоритм)
1. Візьми головну ціль кварталу (з `priorities-quarterly-theme`).
2. Признач їй 1 результатну (lagging) метрику = критичне число.
3. Додай 1–2 випереджаючі (leading), що передбачають результат.
4. Розклади по власниках: у кожного — своє число дня/тижня.
5. Перевір: на кожну метрику хтось РЕАЛЬНО впливає? Ні → прибрати.

## Шаблон scorecard
```
Рівень компанії:
  Smart Number кварталу (lagging): ___
  Leading-метрики (1–2): ___
По командах/людях:
  Роль ___ → число дня/тижня ___ → норма ___ → власник ___
Огляд: щодня на хадлі (число) · щотижня (тренд) · щомісяця (KPI-огляд)
```

## Калібрування 50→100
- При ~50: 1 головне число компанії + по 1 на команду. Не більше — інакше дашборд стає «звітністю».
- Ближче до 100: KPI по функціях, але зберігай правило «одне головне число на рівень».
- Анти-бюрократія: не вимагай ручних звітів — метрика має зніматись із системи/таблиці автоматично.

## Вихід
Scorecard (компанія + ролі) з leading/lagging-розбивкою + список метрик, які варто прибрати як «шум».
