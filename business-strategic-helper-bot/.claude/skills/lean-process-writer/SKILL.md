# Lean Process Writer

## Коли застосовувати
Будь-яке «напиши процес / регламент / інструкцію / політику / чек-лист» або
«цей документ занадто важкий, спрости».

## Тест на бюрократію (обов'язковий, перед видачею)
1. Один явний власник процесу? (Ні → переробити.)
2. Вміщається на 1 сторінку / 1 екран? (Ні → скоротити.)
3. Кожен крок прибирає більше роботи, ніж створює? (Ні → прибрати крок.)
4. Можна асинхронно / self-service замість наради чи погодження? (Так → роби так.)
5. Кількість погоджень ≤ 1? (Ні → обґрунтувати кожне або прибрати.)
Не пройшло — спрости і покажи спрощену версію поряд з поясненням, що прибрано й чому.

## Шаблон SOP (єдиний формат)
```
Назва:
Мета (1 речення):
Власник (роль, не ім'я):
Тригер (коли запускається):
Кроки (мінімум, по одному дієслову):
  1.
  2.
  3.
Результат (як виглядає «готово»):
Що НЕ робимо (щоб не плодити зайве):
Перегляд: раз на квартал або при зміні >X
```

## Принципи
- **Принцип, а не правило.** Дай напрям і межі рішення, не сценарій на кожен випадок.
- **Default + виняток.** Опиши дію за замовчуванням; ескалація — лише за винятком.
- **Self-service.** Замість «напиши керівнику» — шаблон/посилання/доступ, щоб людина зробила сама.
- **Один власник.** Без власника процес мертвий — призначай роль.
- **Видаляй, додаючи.** Додав крок — знайди, який прибрати.
- **Калібрування 50→100.** Формалізуй лише те, що повторюється і вже болить (див. `company-stage-calibrator`).

## Анти-приклади
- Регламент на 6 сторінок «про всяк випадок» → 1 сторінка принципів.
- Ланцюг погоджень 3+ → 1 власник вирішує, інформує решту.
- Обов'язкова нарада для статусу → асинхронний апдейт у каналі.
